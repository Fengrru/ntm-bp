## Caveat: `per_case` is not the case mean

In `experiment_expansion_eval_results.json` and
`experiment_sealed_test_results.json`, the `per_case` object stores **one
representative jitter instance per case** (the last one written), not the
mean over the case's ten jitter instances. Aggregating `per_case` therefore
does **not** reproduce the paper's numbers for methods whose decisions
depend on the jittered confidence (NTM-BP).

This representative-instance convention is used **only** for the paper's
case-level win/loss analysis (Appendix A, ``Bootstrap``); all aggregate F1
values are instance-level macro means. `scripts/experiment_significance.py`
recomputes both and writes `experiment_significance_results.json`.

The canonical numbers are recomputed at the instance level by
`scripts/reproduce_paper_tables.py`. In particular the paper's Table 4
lexical stratification is:

- NTM-BP marked = **0.771**, unmarked = **0.628** (overall 0.686),
- consistent with the instance-level macro metric used everywhere else.

An older ad-hoc script averaged `per_case` and reported 0.736 / 0.619;
that estimator is not the paper's metric.
